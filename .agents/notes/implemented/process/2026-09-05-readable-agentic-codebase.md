# Readable repository guidance and Make Codebase Agentic identity

Status: implemented

## Problem

The earlier suite captured repository record ownership but left much of documentation structure and editorial judgment implicit. The user wants the technical depth, navigation, and language quality seen in DeepSeek Harness, and approved the Make Codebase Agentic rename.

## Decision

The suite keeps eleven skills. Documentation owns focused references for structure, precise prose, codebase explanations, instruction hierarchy, and worked examples. Engineering owns code organization. Setup and review load those owners when needed. The bundle demonstrates useful subtree instructions and preserves one source for each standard.

The source directory, public repository, plugin, skill identifiers, UI invocations, and package use `make-codebase-agentic`. Version 0.2.0 identifies the changed identity and substantive guidance. The installer migrates owned Project Thread skill links, including broken links after a move, after establishing the complete new installation. Raw historical evaluations and original license attribution remain intact.

## Alternatives considered

Renaming only the README would leave discovery, installation, and references inconsistent. Keeping permanent alias skills would duplicate discovery and exceed the eleven-skill boundary. Adding several prose-specific public skills would overlap documentation and make routing less clear. Copying DeepSeek's full instructions would import product-specific tooling, runtime rules, and bilingual obligations. A word-count target would reward losing conditions and guarantees rather than improving understanding.

## Consequences

Current invocations use the new prefix. The [migration guide](../../../../docs/migration.md) covers owned installation links; existing adopting-project record filenames remain valid and are not rewritten by the installer. Detailed guidance has a conditional reading path, while code and documentation still require semantic judgment. File validity does not establish automatic loading in an agent host.

The [engineering foundation](2026-09-05-engineering-ios-suite.md) and [roadmap decision](2026-09-05-area-roadmaps.md) remain active. This decision refines their identity and documentation guidance while preserving engineering, lifecycle, delivery ownership, and evidence rules. It does not fully supersede either record.
