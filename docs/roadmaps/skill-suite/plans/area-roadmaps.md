## Requirement and accepted scope

The user confirmed that a substantial project needs separate roadmaps by product area or major initiative, connected by a lightweight index, then asked to connect issues, separate phase files, and Agent Notes. Each roadmap sequences requirements and feature plans; each plan owns detailed requirements and acceptance criteria and is implemented in verifiable phases. Shared business rules retain their existing documentation owner.

The default groups the overview, plans, issues, and phase files in one roadmap folder. Agent Notes remain linked canonical records in the shared lifecycle tree; existing layouts are supported.

Update the existing eleven-skill bundle, its own planning records, and distribution archive. Existing user installation links should expose the updated source. No new public skill, app feature, or marketplace registration is required.

## Acceptance criteria

- The roadmap skill scopes roadmaps by area/initiative and uses the project index for shared priorities and cross-area dependencies.
- Requirement ownership is explicit: feature plan or existing requirements authority; shared rules remain in product docs.
- Each plan has one primary roadmap owner. Shared capabilities are linked dependencies, and consumers require their own acceptance evidence.
- Setup, daily recovery, feature planning, phase completion, and checkpoints carry the owning roadmap through the workflow.
- Each roadmap can navigate its issues, separate phase records, and linked decisions. Issue resolution, phase completion, and note lifecycle retain distinct meanings, with one authoritative record for each.
- This repository uses an index plus scoped roadmaps without losing the existing completed outcome, candidate, plan links, or evidence.
- Changed skills and the bundle pass validation, required helper checks pass, the archive is refreshed, and all eleven installed links still resolve.
