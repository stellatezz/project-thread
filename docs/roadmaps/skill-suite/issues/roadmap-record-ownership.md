# Roadmap record ownership

Status: resolved

Owning roadmap: [Skill suite](../README.md). Implementing plan: [Area and initiative roadmaps](../plans/area-roadmaps.md). Delivery phase: [Integrate roadmap records](../phases/area-roadmaps/01-integrate-records.md).

## Problem and expected outcome

The initial framework named one default roadmap and kept phases inside feature plans without an explicit issue record. A large product needs scoped roadmaps and a navigable relationship between requirements, actionable issues, phases, and decision rationale.

A session should be able to enter a roadmap overview and find the relevant owners, and enter an issue or note and recover its roadmap/plan/phase. Shared decisions and dependencies must have one owner. Detailed requirements and acceptance are defined by the linked plan; this issue tracks that ownership gap.

## Resolution

Resolved on 2026-09-05. The grouped-record guidance and repository migration establish the requested navigation and ownership. The [phase evidence](../phases/area-roadmaps/01-integrate-records.md) records link/structure checks, semantic ownership review, validated skill entry points, helper regressions, archive installation, and current user-link verification. That evidence establishes the expected outcome; the note's lifecycle is independently maintained.

Decision: [Area-roadmap ownership](../../../../.agents/notes/implemented/process/2026-09-05-area-roadmaps.md). No separate copy of that rationale is maintained here.
