Draft planning conclusions:

- Preserve Vue 3 SSR, existing components/router/query client/authentication. No demonstrated need for a global store.
- URL owns committed search/filter/pagination state; form owns uncommitted text; query client owns results; feature-local dialog owns save name, immutable snapshot and operation state.
- Proposed explicit filter commit pushes one history entry and resets pagination atomically. Back/Forward restores URL-derived controls/results. Typing creates no history entries.
- Proposed save snapshots committed search, excluding pagination; confirm typed-versus-committed semantics and how users retrieve saved searches.
- Reject rendering-time localStorage initialization because of server availability and hydration consistency. Current requirements need in-session name preservation, not assumed durable storage.
- Preserve public server-rendered catalog content, metadata and established canonical/indexing rules. Keep private data out of shared SSR caches.
- Scope async state by normalized query, page/cursor, identity and session/request generation. Guard success, failure and cleanup; cancellation alone is insufficient.
- Old responses must never replace new results, append old pages, clear newer loading, or publish prior-account data/toasts.
- Expiry/account switching invalidates pending work and private caches using existing auth policy. Preserve recoverable same-account drafts without exposing/resubmitting them under a different identity.
- Model save as editing/submitting/confirmed/recoverable-error/outcome-unknown/auth-required. Preserve name and payload on recoverable failures. Block duplicate submission.
- Timeout does not establish failure. No automatic mutation retry or unrestricted resend until backend idempotency or authoritative reconciliation is contracted. A delayed-success mock proves neither persistence nor duplicate prevention.
- Reuse an accessible shared dialog: labels, connected errors, announcement, visible/contained keyboard focus, Escape policy and focus return. Closing a pending dialog cannot claim server cancellation. Check mobile software keyboard and long-content layouts.
